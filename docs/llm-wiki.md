## 1. 효과적인 프롬프트 패턴

### ✅ 잘 된 패턴

**정보 → 질문 → 가정 → 설계 순서로 요청하기**
```
나는 [한 줄 주제]를 만들고 싶다.
조건: [플랫폼], [기능], [팀 경험]
요청:
1. 빠진 정보가 있으면 질문 먼저 해줘
2. 추측한 내용은 "가정"이라고 표시해줘
3. 답변 후 설계 방향을 제안해줘
```
→ AI가 바로 만들기 전에 조건을 확인하게 해서 결과물 품질 향상

**산출물 형식을 명확히 지정하기**
```
출력 형식:
1. 디렉토리 트리
2. docs/architecture.md 초안
3. Mermaid 다이어그램 코드
4. ADR 초안 3개
```
→ 원하는 형식을 미리 지정하면 재요청 횟수가 줄어듦

**실제 파일 만들기 전에 계획 먼저 보여달라고 하기**
```
실제 파일을 만들기 전에 변경 계획을 먼저 보여줘.
```
→ 잘못된 방향으로 가기 전에 검토 가능

---

### ❌ 잘 안 된 패턴

**너무 막연한 요청**
```
게임 UI 만들어줘  (❌)
Flutter로 로그라이크 던전 게임의 전투 화면 UI를 만들어줘.
좌측에 캐릭터, 우측에 몬스터, 하단에 HP바 구성.  (✅)
```

**한 번에 너무 많은 걸 요청하기**
```
전체 앱을 다 만들어줘  (❌)
스플래시 화면 하나만 먼저 만들어줘  (✅)
→ 화면 단위로 나눠서 요청하는 게 품질이 훨씬 좋음
```

## 2. Flutter 개발 중 AI로 해결한 문제들

### 자동전투 틱 속도 문제
- **문제:** Timer 주기가 너무 짧아 UI가 버벅임
- **프롬프트:** "Flutter에서 게임 루프를 Timer로 구현했는데 성능이 떨어짐. 최적화 방법 알려줘"
- **해결:** Timer 주기 조정 + 불필요한 setState 제거
- **교훈:** 성능 문제는 문제 상황을 구체적으로 설명할수록 좋은 답변이 나옴

### Provider 상태 충돌
- **문제:** 전투 상태와 로비 상태가 같은 Provider를 공유해서 충돌
- **프롬프트:** "Flutter Provider에서 두 화면이 상태를 공유할 때 충돌 나는 문제 해결 방법"
- **해결:** 별도 ChangeNotifier로 분리
- **교훈:** 에러 메시지를 그대로 붙여넣으면 더 정확한 답변이 나옴

### Firebase 초기화 순서 문제
- **문제:** Firebase가 초기화되기 전에 앱이 실행되어 오류 발생
- **프롬프트:** "Flutter Firebase 초기화 순서 문제, main()에서 어떻게 처리해야 하나"
- **해결:** main()에서 WidgetsFlutterBinding.ensureInitialized() 후 Firebase.initializeApp() 순서 보장
- **교훈:** Flutter 초기화 순서는 반드시 공식 문서 기준으로 확인

## 5. 이번 프로젝트 핵심 교훈

1. **AI는 초안 담당, 검토·수정은 내가** — AI가 만든 걸 그대로 쓰면 발표 때 설명 못함
2. **화면 단위로 나눠서 요청** — 한 번에 많이 요청할수록 품질 저하
3. **에러는 메시지 그대로 붙여넣기** — 요약하면 AI가 잘못 이해함
4. **ADR로 결정 이유 기록** — 나중에 "왜 이걸 선택했나요?" 질문에 즉답 가능
5. **AUTHORING.md로 부트스트랩** — 다음 프로젝트에서 30분 안에 전체 문서 생성 가능

## 6. 재사용 가능한 프롬프트 템플릿

### 기획 문서 생성
```
나는 [앱 주제]를 만들고 싶다.
1) 비전과 목표를 .planning/00-vision.md에 작성
2) 핵심 사용자 시나리오 3개를 .planning/01-requirements.md에 작성
3) 기능을 MoSCoW(Must/Should/Could/Won't)로 분류
4) 모호한 부분은 선택형 질문으로 물어봐줘
```

### 아키텍처 설계
```
아래 조건으로 앱 초기 구조를 설계해줘.
- 레이어: Presentation, Application, Domain, Data
- 각 레이어 책임을 한 문장으로 설명
- 핵심 기능 3개가 어느 레이어를 지나는지 표로 정리
- 플랫폼별 관례에 맞는 디렉토리 구조 제안
산출물: 디렉토리 트리 + architecture.md + Mermaid 다이어그램 + ADR 초안 3개
```

### 테스트 코드 생성
```
이 함수의 단위 테스트를 작성해줘.
조건:
- happy path 1개
- edge case 3개 (빈 입력, null, 경계값)
- 이름은 should_~_when_~ 형식
```
