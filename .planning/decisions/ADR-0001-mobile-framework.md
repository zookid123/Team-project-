# ADR-0001: 모바일 프레임워크 선택

- **상태**: Accepted
- **날짜**: 2026-05-19
- **결정자**: 팀

## 배경

iOS/Android 동시 지원이 필요하며, 자동전투 실시간 렌더링과 절차적 던전 생성 로직을 처리해야 한다.
일반 앱 프레임워크(Flutter, React Native)와 게임 엔진(Unity) 중 선택이 필요했다.

## 고려한 대안

### 대안 A: Flutter (Dart)
- 장점: 단일 코드로 양 OS, Hot Reload, UI 위젯 풍부, AI 학습데이터 多
- 단점: 게임 루프·파티클·애니메이션 렌더링에 구조적 한계. Dart 학습 필요

### 대안 B: React Native (TypeScript)
- 장점: JS/TS 친숙하면 빠른 진입, Expo로 쉬운 환경 구축, npm 생태계 거대
- 단점: 성능 민감 영역 결국 네이티브. 게임 특화 기능 부재

### 대안 C: Unity (C#)
- 장점: 게임 엔진 특화 최적화, 물리·애니메이션·파티클 내장, 양 OS 단일 코드베이스, 무료 에셋 마켓
- 단점: Unity 학습 비용, IL2CPP 빌드 시간 증가, 앱 기본 용량 큼

## 결정

**Unity (C#)** 를 선택한다.

## 이유

- 로그라이크 던전 RPG는 자동전투 애니메이션·파티클·실시간 렌더링이 핵심 기능
- Flutter/React Native는 일반 앱에 최적이나 게임 루프 렌더링에 구조적으로 부적합
- Unity는 AssetBundle로 앱 용량 분리 가능하고, 무료 에셋으로 빠른 프로토타이핑 가능

## 결과

**긍정:**
- 게임 특화 최적화 가능
- 양 OS 단일 코드베이스 유지
- 무료 에셋 마켓으로 개발 속도 향상

**부정 / 제약:**
- Unity 학습 초기 비용 발생
- IL2CPP 빌드 시간이 Flutter 대비 길어짐
- 앱 기본 용량이 상대적으로 큼

## 60초 발표 요약

> "저희 게임은 자동전투 애니메이션·절차적 던전 생성 등 게임 엔진 기능이 핵심이라,
> 일반 앱 프레임워크(Flutter/React Native)가 아닌 Unity를 선택했습니다.
> 대안으로 Flutter를 검토했으나 게임 루프 렌더링에 구조적 한계가 있었고,
> Unity는 양 OS를 단일 코드로 지원하면서 게임 최적화를 그대로 가져갈 수 있는
> 유일한 선택지였습니다."
