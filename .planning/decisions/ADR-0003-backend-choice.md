# ADR-0003: 로컬 저장 방식

- **상태**: Accepted
- **날짜**: 2026-05-19
- **결정자**: 팀

## 배경

메타 진행 데이터(영구 해금·스탯·런 기록)를 기기에 어떻게 저장할 것인지 결정이 필요했다.
외부 서버 없이 로컬에서 완결되는 저장 방식을 채택해야 했다.

## 고려한 대안

### 대안 A: PlayerPrefs
- 장점: Unity 기본 제공, 즉시 사용 가능, 코드 간단
- 단점: Key-Value 구조라 복잡한 데이터 저장에 부적합. 용량 한계 있음

### 대안 B: JSON + Application.persistentDataPath
- 장점: 구조화 저장 가능, 버전 관리 용이, 디버그 시 파일 직접 열람 가능
- 단점: 직렬화/역직렬화 코드 직접 작성 필요. 암호화 별도 처리 필요

### 대안 C: SQLite (via Unity 플러그인)
- 장점: 관계형 데이터 저장에 강함, 쿼리 가능
- 단점: 플러그인 의존, 6주 프로젝트에 과도한 복잡성

## 결정

**JSON 파일 저장 (Application.persistentDataPath)** 을 선택한다.

## 이유

- 메타 진행 데이터는 캐릭터·해금·런 기록 등 구조가 복잡해 PlayerPrefs 한계 초과
- SQLite는 6주 프로젝트 규모에 과도함
- JSON은 Unity의 JsonUtility로 간단히 직렬화 가능하고 디버그 편의성 높음

## 결과

**긍정:**
- 데이터 구조 변경 시 마이그레이션 가능 (버전 번호 관리)
- 디버그 시 save.json 파일 직접 열람·수정 가능
- PlayerPrefs 대비 복잡한 데이터 구조 자유롭게 저장

**부정 / 제약:**
- 저장 실패 예외처리 코드 필수
- 암호화 없으면 치팅에 취약 (현 단계에서는 허용)
- 저장 스키마 변경 시 기존 데이터 마이그레이션 필요

- [ ] 예외처리 — 파일 없을 때 기본값으로 초기화 로직 구현
